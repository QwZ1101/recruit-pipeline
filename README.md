# 校招智能投递助手

把 **采集岗位 → 匹配排序 → 台账跟踪 → 状态同步** 串成一条可复现的管线。
定位是半自动:程序负责找岗、排序、记账,**决定投哪个、点投递按钮的是人**。

## 为什么不做全自动投递

招聘平台的批量点击投递受风控约束,且代投违反服务条款;更实际的问题是自动海投的转化率极低,
还会把台账搞成没人看得懂的垃圾堆。所以这里只做"辅助到只差一次点击"。

## 管线

```
简历 PDF ─parse_resume.py→ data/resume.json ─
                                              │  硬门槛正则过滤
research/scan_ai_jobs.py(31 家北森租户公开接口采集)   │  embedding 粗筛 Top30
   → data/ai_jobs.json(1550 个 AI 岗)                  │  ↓
research/moka_collect.js(Moka 站在浏览器里抄 DOM)       │  LLM 精排(增量,复用旧结论)
   → data/moka_raw.json → merge_moka.py 并进同一个池     │  ↓
   → data/shortlist.json(本科可投 + 开发向 385)─────────┘
                                       data/match_result.json + 投递优先级.md
                                                  │  store.py ingest(rank_jobs 末尾自动调)
                                                  ↓
              data/ledger.db = apps/history(可写状态) + pool/meta(只读岗位数据与画像)
                                                  │
        ┌─────────────────────────────────────────┼──────────────────────────┐
  ledger.py sync                     src/api.py(FastAPI,只绑 127.0.0.1)  ledger.py report
(北森侧状态回写,页面「同步北森」同一函数)   读写台账 → /api/pool 给看板         → 投递台账.md
                                                  ↓
                                     Vue3 看板 http://localhost:5173
                          点状态胶囊即写库;命令行改了库,页面 12 秒内跟上
```

## 快速开始

```powershell
# 1. 后端环境(Python 3.13)
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:PYTHONIOENCODING = "utf-8"        # 否则中文输出会炸
$env:DASHSCOPE_API_KEY = "sk-..."      # 阿里 DashScope 兼容模式

# 2. 跑管线
python research\scan_ai_jobs.py                                  # 采岗位池(约 3-6 分钟,不花钱),顺带打与上一版的 diff
# Moka 站接口是密文,得在浏览器里抄 DOM 再合并 —— 见下面「采 Moka 站」一节
python src\parse_resume.py "AI应用开发工程师简历（新版）.pdf"   # 简历 → 画像
python src\rank_jobs.py --plan       # 先看这次要新调几次 LLM,一次都不花钱
python src\rank_jobs.py                                        # 门槛过滤 + 粗筛 + 精排(只花新增岗位的钱),末尾自动入 SQLite
python src\ledger.py init --from-rank                          # 新岗位进台账(已存在的不覆盖状态)

# 3. 看板:两个终端
python src\api.py                            # 后端,只监听 127.0.0.1:8000
cd web; npm run dev             # 前端 http://localhost:5173,/api 由 vite 代理
```

日常只有两种动作:

```powershell
# 投出去一个:页面上点状态胶囊(待投 → 已投),或者命令行
python src\ledger.py done <短码>
# 想知道北森侧走到哪了:页面点「同步北森」,或
python src\ledger.py sync
```

## 前后端接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/pool` | 看板全量数据(含 `transitions`,前端照它渲染下拉,不自己判规则) |
| `GET` | `/api/apps/{key}` | 单条台账 + 它的状态历史 |
| `PATCH` | `/api/apps/{key}` | 改状态,可带 `note` / `force`;`已投` 自动记投递时间 |
| `POST` | `/api/apps/{key}/note` | 追加备注(用 ` \| ` 拼,不覆盖) |
| `POST` | `/api/sync` | 拉北森侧真实状态,`dry_run` 只预览 |
| `GET` | `/api/profile` | 投递表单答案表,给 `web-ext/` 自动填充用 |
| `POST` | `/api/pool/moka` | Moka 采集器落盘口:只覆盖 `data/moka_raw.json` 里对应 `(org, siteId)` 那一段,校验不过就 400 |
| `GET` | `/api/pool/moka.js` | 把采集器源码吐给页面执行(同一份实现,人贴控制台和 agent 驱动无差别);CORS 只认 `app.mokahr.com` |

三条约定,改代码前先看:

1. **写路径只有一条。** 页面按钮 → `api.py` → `ledger._set()`,状态机规则不在 JS 里重复一份。
   `LedgerError` 在 CLI 打印退出、在 HTTP 返回 400。
2. **库是唯一真相,JSON 是快照。** `data/*.json` 由流水线写出、`store.py ingest` 灌进 `ledger.db`;
   页面和 `.md` 报告都从库里渲染,不做双向写。
3. **只在本机。** 库里是手机号、邮箱、投递记录,`api.py` 拒绝绑非 127.0.0.1。

台账直接用 DataGrip / DB Browser 打开 `data/ledger.db`:
`apps`(状态)、`history`(流转流水)、`pool`(岗位内容与精排结论)、`meta`(统计与画像)。

## 采 Moka 站(北森之外)

不少公司不用北森,用 Moka(已采:DeepSeek、月之暗面 Kimi、作业帮、涂鸦智能、燧原科技、
智谱、阶跃 StepFun、大疆、银河通用机器人):
`https://app.mokahr.com/<social|campus>-recruitment/<org>/<siteId>/#/jobs`。
**这类站不能像北森那样 curl** —— 它的 `/api/outer/ats-apply/website/jobs/v2`、`/jobs/module`
一律返回 `{"data":"<一坨 base64>","necromancer":...}`,明文是它自家前端 JS 在浏览器里解出来的,
带着 cookie 和 csrf 头也一样。逆向那套解密技术上能成,但那是绕人家的反爬措施,而且对方换 key 就全废,
**所以这里不做**。改抄已经渲染到页面上的文字,和一个人翻页面看到的东西完全一样。

```powershell
python src\api.py                                   # 落盘口在后端,先开着
# 1) 浏览器打开 https://app.mokahr.com/social-recruitment/high-flyer/140576/#/jobs
# 2) F12 → Console,整段粘贴 research\moka_collect.js 回车
#    它自己跟分页器翻完所有页,把结果 POST 到 127.0.0.1:8000/api/pool/moka → data/moka_raw.json
#    (控制台看到 postedToBackend: true 才算成了;下载那条路在内置浏览器里会被静默丢掉)
# 3) 归一并进池子,重建 shortlist(不覆盖状态,只写 ai_jobs.json / shortlist.json)
python research\merge_moka.py --dry                 # 先看会新增/更新/下架几条
python research\merge_moka.py
python src\rank_jobs.py --plan                      # 新岗位会挤进 Top30,先看要调几次 LLM
python src\rank_jobs.py
```

口径上的三件事:

- 岗位 `id` 用 Moka 的 job uuid、`tenant` 写成 `moka:<org>`,和北森的 `J…` 编号天然不撞;
  精排结论缓存的 key 是「画像 + JD 正文」,所以 Moka 岗复用同一套缓存,不用重算北森那 26 条。
- 新站要先在 `research/tenants.py` 的 `MOKA_SITES` 登记 `siteId` 和中文名,否则报告里只显示别名。
- 多数站点的列表卡片 `.expand-area` 就是 JD 全文,翻完分页即采完;**但不是所有站都这样**
  (作业帮、天数智芯的卡片只有标题+地点)。正文短于 80 字的会跳过并打印,那既可能是
  "点我投递到别的岗位"的转链占位,也可能是这个站根本不在卡片里放 JD —— 用 `detail` 模式补(见下)。

### 还有哪些公司用 Moka:`research/probe_moka.py`

不用搜索引擎猜,直接问 Moka 自己:

```powershell
python research\probe_moka.py            # 一批候选别名,结果写 data/moka_sites_probe.json
```

原理是**看 302 的 `Location`,不看响应体**:
`GET https://app.mokahr.com/<social|campus>-recruitment/<org>/` 不带 siteId 时,
存在的 org 会被 302 到它的**默认站点**(Location 末尾那串数字就是 siteId);不存在的 org
返回 200 的 SPA 外壳 —— 它对所有路径都发同一个壳,状态码没有信息量。
`urllib` 默认会跟着跳,要用 `_NoRedirect` 把 302 拦下来才读得到 Location。

三个坑,每个都是实测踩出来的:

1. **默认站点不等于在招的那个站。** DeepSeek 的默认站 4604 里 0 个岗位,真站在 `140576`;
   `xiaopeng` 的默认站是子品牌「汇天」。所以 probe 只用来**发现别名**,`siteId` 必须打开页面
   用渲染出来的岗位数和 `<title>` 确认后才能进 `MOKA_SITES`。
2. **别名会撞车。** `agibot` 打开来是「敏捷医疗」,不是我以为的智元机器人。
   公司中文名一律从页面 `<title>` 抄,不从别名推(`MOKA_SITES` 注释里记着这个教训)。
3. **有的站整家是空的或全是芯片岗。** 探到 ≠ 值得采:`jd`/`agora` 空站,`iluvatar` 全是 IC 向,
   `robotera` 全是硕士向具身算法。没登记的在 `MOKA_SITES` 注释里留了原因,别重复采。

卡片没 JD 的站要逐个进详情页,采集器带 `detail` 开关(只在 `only` 正则命中的标题上跑,
否则 64 个岗要等几分钟):

```js
window.__mokaCollect({detail: true, only: '开发|工程师|算法|AI', download: false})
```

由智能体驱动时不能靠"人 F12 粘贴",走的是同一段代码、另一条投递路径:
后端 `GET /api/pool/moka.js` 把 `research/moka_collect.js` 原文吐出来(CORS 只认 `https://app.mokahr.com`),
页面里 `fetch` 进来 `eval`,再在 **iframe** 里指向目标招聘站执行 —— 同源,所以能读它的 DOM。
浏览器工具的脚本执行有 **15 秒上限**,而采一个站要几十秒,所以是**发出去不等**:
结果挂在 `window.__MOKA_RESULT` / `__MOKA_ERROR`,外面轮询读。落盘仍然只有 `POST /api/pool/moka` 一个口,
按 `(org, siteId)` 覆盖、其余保留,一家一家采不会互相冲掉。
多站串在一起跑也行:同一个 driver 里 for 循环建 iframe → `await __mokaCollect(...)`,进度挂在
`window.__RUN.log` 上外面看。**但先用一次 iframe 抓一页标题列表判死活(约 8 秒),再决定采不采** ——
"标题渲染正常、列表 0 条"说明 siteId 不对或那个类目没开放(第四范式、云从、擎朗、海能达、途虎全这样),
而"有站但没有技术岗"的更多(好未来 150 条首屏 0 个技术岗、Shopee 只剩 3 条管培)。

采到这里 Moka 这条线的性价比基本见底了:**设有 AI 应用/全栈工程岗的公司才有增量**(作业帮 3 投、阶跃 2 投),
头部大模型公司(智谱、月之暗面、银河通用)在 Moka 上放的是研究序列,本科 + 应用开发画像连 Top30 都进不去。
再要涨「投」的数量,得去别的 ATS(飞书招聘、博思 wecruit)或实习转正通道找。

## 自动填充扩展(`web-ext/`)

每家北森门户的投递表单都要重答一遍证件号/户口/教育经历,所以做了个 Chrome 扩展。
**它只填字段,不点提交**——最后一步永远是人,和「不做全自动投递」是同一条线。

装与用:

```powershell
python src\api.py                                   # 扩展从 127.0.0.1:8000/api/profile 取数,后端得开着
# chrome://extensions → 开「开发者模式」→ 加载已解压的扩展程序 → 选 web-ext/
# 打开任意 https://<租户>.zhiye.com 的投递页 → 右下角「自动填充」
```

行为约定:

- 按 **label 文本**定位输入框,不写死 selector(各家租户字段名和必填项不一样)。
- 页面**已有值的一律不覆盖**,只在报告里列出来;下拉停在「请选择」才算没填。
- 答案表里是 `null` 的字段跳过并提示你手填,**不猜**。省市区级联按 `native_province / native_city /
  native_county` 三级逐级点,少一级就整字段报 ✋ 手选(不猜剩下两级)。
- **弹层类字段(下拉/日期)按人的方式填:点开 → 在弹层里点中那一格 → 回读显示框**。
  往 readonly input 里写 value 只改显示、不改组件自己的 state(实测出生日期写进去以后
  日历还停在 2004-01-01),所以写值只是**兜底**,而且必须落在 `👀` 那一栏。
  怎么"认出弹层"是关键:**不猜 class**(上一版按 `dropdown/picker/cascader/overlay` 找容器,
  真实页 8 个字段全哑,夹具却全绿 —— 假组件是我照着自己的想象捏的)。现在是**可见性快照差分**:
  点之前把页面上所有可见元素记成集合,点之后只看哪些节点是**新出现**的。
  护栏:① 只在"因为这次点击才出现"的节点里找(页面别处早就渲染好的同名文案永远点不到);
  ② 只点**文案与答案 `norm` 完全相等**的叶子节点,不做子串匹配;
  ③ 点完回读显示框,对不上就当没填、退回 `🔒` 报手选 —— **只有点中且回读一致才进 `🎯`**;
  ④ 日历**按"点一下看它干了什么"认翻页按钮**,不按 `« ‹ › »` 找字符(真实页箭头是图标字体/CSS
  伪元素,`textContent` 是空的,按字符找必然找不到)。做法:在抬头附近挨个小按钮,点完回读抬头,
  算出它让年月走几格(+1 月 / +12 月 / 不动),记下再按需要的步长走;
  **抬头没翻到目标年月就绝不去点格子**,所以最多是白翻两页,填不进错值。
  两种面板都要认:整日期走 `openDate`(抬头 `2004年11月` + 日格),子弹表里 `2023-09` 这种**年月值**
  走 `openMonth` —— 北森给的是「`« 2026 »` + 12 个月格」的月面板,没有日格。
  **候选按几何筛,不按"长得像不像按钮"筛**:只认**和抬头在同一条横带上**、≤80×80、文字 ≤2 字符、
  没有带文字后代的小节点。以前用"文字短 + 后代也没字"当判据,真实页(2026-09-26 16:15)那八个候选里
  混进了**日历的日格和空白补位格** —— 点中一格等于替用户选了一天(出生日期被写成 2004-01-01),
  而抬头一动不动,所以报出来的位移全是 0。日格/星期表头/「今天」「本月」都在抬头下面,横带一卡就进不来。
  再加一条**停手护栏**:每次点击前后回读 `el.value`,它一变就说明刚才那一下是"选择"不是"翻页" ——
  立刻停止、把改成的值报进 `🔍 诊断`(`探测翻页按钮时点到了 td.dp-cell「1」,把值改成了…`),
  绝不继续点、也绝不再去点格子。诊断里现在**逐个列出每个候选是谁 + 实测走几格**,一张截图就能定案。
  点击热区按 `input 本身 → 组件壳 → 壳的上一层` 逐个试,每个热区再分**完整点击**和**只按下不松开**
  两种按法(有的组件 `pointerdown` 就开、`click` 又把它收回去);全都失败就写一行 `🔍 诊断`
  进面板(试到第几个热区、冒出来几段什么文字)—— **让面板自证,别再让下一轮靠猜**。
- **点击的范围(用户 2026-09-25 放开假控件、2026-09-26 放开弹层和级联)**:纯 div 假单选/假下拉 +
  上条说的弹层选项 + **省市区级联**。级联必须逐级点完再点弹层里的「确定」才算选中(不点就丢弃),
  这是全模块**唯一允许点的按钮**,护栏三条:它得是"点上一级之后才出现的"节点、在那次点开的容器子树里、
  文案正好是「确定」。提交/下一步在页面别处,撞不上这几条,永远不点。
  点完「确定」的回读**认"点开弹层之前就在这行里、当时就看得见"的那些节点**(`op.before` 里筛),
  外加**整行所有 input 的当前值**。理由:真实页的面板就长在字段行里,省市区那几个名字本来就在行文字里,
  拿整行文字当"已选中"会假阳(值其实被丢弃了);而反过来按"把弹层容器挖掉"来排除又不行 ——
  真实页显示「示例县」的是**同行另一个 input**,我们手里那个 readonly 框一直是空的,

## 踩过的坑(都写进代码注释了)

- 北森 `GetJobAdPageList` 的 **`pageIndex` 从 0 开始**,不是 1。按 1 起翻每页都正常返回、`Count` 也对得上,只在末尾少一页 —— 于是**每个租户的头 10 个岗位静默丢掉**,`Count<=10` 的小租户整家拿到 0 条。特征是「实取恒等于 Count-10」,当时 62 个租户×类目有 60 个中招,却全被 `缺!` 警告刷过去了。
- 北森 `GetJobAdPageList` 的 **`pageSize` 只能用 10**,给 20/50/100 会返回不完整页甚至空 `Data`,但 `Count` 仍然正确 —— 静默漏数据。
- **`keyWords` 服务端过滤不可用于取数**:`Count` 准但 `Data` 常为空,只能全量拉回本地过滤。
- 职位列表和详情**只有 9 个字段有值**,`Station`(城市)、`Degree`(学历)全空 —— 企业没填。城市和学历必须从 JD 正文正则抽取。
- 无效租户返回 **HTTP 200 + 非 JSON**(通配 DNS),判存活不能只看状态码。
- 北森登录 Cookie(`user_v2`)**按租户隔离**,不共享 `*.zhiye.com`;每家要单独登录、单独存 `data/secrets/beisen_cookie.<租户>.txt`。
- **一页里写多个子方向的"团队 hub 岗",学历要取最宽松的那档,不是第一条命中的。** DeepSeek 的
  「Agent Harness 团队」先写研究员要"硕士学历及以上"、后面研发工程师写"知名高校本科",按第一条抽成硕士,
  这个岗就被"本科可投"那道筛选误杀了(而且它恰好是最对口的一个)。`jobrules.degree_of` 现在按
  `LOOSEST_FIRST` 顺序取;更严的"硕士及以上"另有 `rank_jobs` 的 `DEG_BLOCK` 拦,不会因此放进不能投的岗。
- 「知名高校 / 名牌大学 / 顶尖院校」这类**没说死层次**的措辞,只在 JD 的**要求段**里当硬门槛
  (`rank_jobs.SCHOOL_SOFT` 只查 `require`,标题里出现不算)。它确实卡民办本科 —— DeepSeek
  「Agent Harness 团队」就是这么被拦在精排之前的,不是漏采。放标题上会误杀,海外/远程岗已经踩过一次。
- 抓取时的 `degree` 是**存进 `ai_jobs.json` 的**,改了抽取规则不会自动生效在北森那 1098 条上,
  要等下次真跑 `scan_ai_jobs.py` 重新抓取才重算(`merge_moka.py --rebuild` 只用现有字段重建清单,不重抽学历)。
  改规则后先比对北森侧漂移了几条,本次改动是 0 条。
- 精排分数由 LLM 给出,**同代码连跑有 ±7 抖动** —— 只信档位(85/82/78),不信名次。
- 简历解析器会**静默丢掉**项目里的 URL 和 JD 关键词,所以提示词里强制"URL 原样抽取、技术用词不得同义改写"。
- 自动填充里**黑名单必须终止整个字段的匹配**,不能"这个标签不行就试下一个候选":
  试过下一个,「短信验证码」被拒后会拿到**上一行**的标签,把学校名填进验证码框。
- 下拉选项匹配要**先剔掉空文案的 option**:`'城镇'.includes('')` 恒真,
  「请选择」会被当成命中项,结果是"报告说填了、实际还停在请选择"。
- **`readOnly` 的检查不能放在 label 匹配之前** —— 那样只读字段连"没匹配上"都报不出来,
  面板会显示「待你补 0」而页面上空着一片。现在先认标签再分流:只读的进 🔒 并附上该填什么。
  (注意:真实北森页那批字段**不是** readonly 被跳过,是下面那条爬层数不够 —— 别把两件事混了。)
- 北森还有一批**div 假控件**(自定义单选、假下拉),`querySelectorAll('input')` 压根看不见。
  所以加了反向扫描:页面上有标签、却没有任何控件被碰到 → 列进 🚫。静默漏字段比填错更难查。
- **漏字段的最大真凶是 label 往上爬的层数不够**。北森 `phoenix` 组件把标签放在与
  `.form-item__control` **平级**的 `.form-item__title` 里,而 select/日期/级联的真 input
  距 `.form-item` 有 **9 层**(`phoenix-unmodeled-layer` 套了 5 层壳,探针实测),普通文本框
  `.phoenix-input > input` 只有 3 层。所以真实投递页**一次性静默漏掉 12 个字段,而文本框全填好了** ——
  这种"简单字段全对、复杂字段全漏"的分布本身就是线索。上限从 5 → 8 仍差一层,现在 **12 层**,
  并加护栏:某层容器里控件超过 3 个就停 —— 那已经爬出行外,再往上取到的全是别的字段的标签。
  跨行污染另外还靠"候选节点子树里含控件就拒绝"挡住。
- **性别、应届/往届 是纯 div 假控件**,整行没有一个 `input/select/textarea`(探针实测)。
  这类只能"点开再选中",也就是要**合成点击**,和「只填不交」是两条线 —— 放开与否由用户决定,不许自己加。
- **别名是子串匹配,长说法必须显式写出来**。「紧急联系电话」包含别名「联系电话」,不补长别名就会被通用电话命中,
  **把申请人自己的手机号填成紧急联系电话**(真实投递页就这么错过)。靠 `KEYS` 按长度倒序 + 补
  `紧急联系人/紧急联系电话/紧急联系人电话/紧急联系方式` 修掉,夹具里留了这两行当哨兵。
- **裸别名会撞上不相干的字段**。「证件」这条本来是为了"证件"这种简写加的,结果它命中了
  **证件照**(上传框):假控件那一路拿着答案「身份证」满行找文案相等的叶子节点,只差一点点
  就点上了上传。现在删掉裸「证件」,并把 `照片/上传/附件/头像` 加进 `BLOCK`;夹具里留一行
  证件照哨兵,断言它不出现在任何清单里。
- **学位 ≠ 学历**:同一个下拉里「本科」是学历的答案、「学士」是学位的答案,混成一个键就会
  把「本科」塞进学位下拉。现在 `最高学历/学历 → degree`,`最高学位/学位 → degree_type`(新键,
  留 null 让你填)。同理新增 `college`(学院名称,不是院校名称)、`study_mode`(学习形式)、
  `target_industry`(期望从事行业)、`expected_salary` 的长说法 `期望月薪`。
- **子表的列名绝不能进全局别名表**。「开始时间/结束时间/语言类型/掌握程度/听说」在页面上出现好几行
  (教育经历一段、项目经历一段),`ALIAS` 里写死一个键就会把教育经历的起始月填进项目经历。
  现在改成**二维定位**:分区(前面最近的可见标题)+ 该分区的列表,见上面「子表」那条约定。
- **写值 ≠ 填上**。往 readonly/假下拉的 input 里 `setNative` 只改显示,组件 state 不认
  (实测出生日期写了 2004-11-01,点开日历还停在 2004 年 1 月)。所以弹层字段改成
  **点开→点等值选项→回读显示框**,回读对不上就不算填。副作用:引擎必须变异步,整页十几秒。
- **猜 class 名去认弹层,是第二轮瞎猜**(2026-09-26 真实页)。第一版弹层驱动按
  `[class*="dropdown"], [class*="picker"], [class*="cascader"]…` 找容器,真实页 9 个下拉/日期
  字段**一个都没命中**(全落在 `👀 弹层没点到选项`),而夹具跑分完全正常 —— 因为**夹具里那个假组件
  是我照着自己的猜法捏的**,它当然顺着猜走。判据换成**可见性快照差分**(点前记录所有可见元素,
  点后只认"新出现的节点")才与实现无关,顺带比原来更安全:没因自己点击而冒出来的文案永远点不到。
  教训两条:① 逆向第三方 DOM 不要拿"class 名长得像"当证据;② **让工具自证** —— 现在引擎把
  每个失败字段"试到第几个热区、冒出来几段什么文字"写进面板 `🔍 诊断`,一张截图就能定死下一版怎么改。
- **夹具要按真实页的"没测过的形态"补**,不然它只会替旧假设背书。这轮加了三处:出生日期和生日
  **共用同一块日历**(真实页就是这样,要测"同一弹层被连续开两次")、`div` 假下拉但**选项不在 DOM 里**
  (断言一个节点都不点、进 `❓`)、`民族` 那种只有一个只读显示框、点开什么也没有(断言停在 `🔒`)。
- **后台标签页会把测量拖慢几十倍**:Chrome 对隐藏页面的 `setTimeout` 先节流到约每秒一次,
  页面藏过 5 分钟后进入 intensive throttling —— **每分钟一次**。这时候引擎看着就是"卡死不动"
  (点击计数几分钟不涨),而它只是在等一个 timer。判引擎快慢前先看 `document.hidden`;
  切不到前台就先 `window.setTimeout = (f, m, ...a) => orig(f, 0, ...a)` 再跑,只验对错。
  (代价:`waitGrown` 那种"轮询到预算用完"的循环会从睡眠变成忙等,所以打码后的总耗时**不能**当性能数据。)
- **日历的翻页箭头不是文字**(2026-09-26 真实页)。`« ‹ › »` 那四个字符在真实页一个都找不到 ——
  它们是图标字体/CSS 伪元素,`textContent` 是空的;而夹具里的假日历**恰好把字符写在了 DOM 里**,
  所以夹具绿、真实页报 `面板里没有「」这个翻页按钮`。现在不按字符找,改成**挨个点抬头旁边的小按钮、
  点完回读抬头看年月走了几格**。这条路能成立是因为每一步自证:方向错就拉黑那个节点,
  而**没翻到目标年月就绝不点「日」**,最坏是白翻两页,不会填进错值。
- **级联的回读曾被自己的面板骗到**。真实页把弹层渲染在**字段行内部**,`shownOf` 取整行文字时
  把面板里的「示例县」也算进去了 → 三级都点、却没点「确定」(值其实丢弃了)也报成功。
  **同一个 bug 的反面当天也发生了**:改成"把自家面板容器挖掉再取行文字"(`rowTextExcept`)之后,
  真实页又报「行里现在显示空」—— 因为它把值写进了**同行另一个 input**,而我们手里那个 readonly 框
  一直是空的,`boxes[0]` 那个容器同时罩着唯一能证明成功的显示节点,挖过头就把证据一起挖了。
  现在的判据是**"点开弹层之前就在这行里、当时就看得见"**(拿 `op.before` 那一张快照筛),
  再加**全行所有 input 的当前值**:面板里新长出来的节点一律不算(防假阳),
  行里原有的显示框和兄弟 input 都算(防假阴)。教训:**回读的取值范围不能假设就是我们匹配到的那个控件**,
  也别用"容器边界"去近似"是不是弹层" —— 用时间边界(开弹层前 vs 开之后)判最准。
- **「抬头旁边一个翻页按钮都没找到」是爬的层数不够,不是真没有按钮**(2026-09-26 真实页)。
  抬头是 `<div class=title><span>2026</span></div>«, »,« »` 那种结构,箭头挂在**再上一层**的 header 行里,
  只爬一层(`head.parentElement`)刚好扫不到 —— 而人眼看着箭头明明就在左右角。这和上一轮"label 爬 5 层
  不够"是同一类错:**第三方 DOM 的嵌套深度不是常数**。现在干脆不爬 —— `navCands` **扫整块面板**,
  靠几何条件筛,层数就不再是参数。
- **候选"小按钮"不能按文字形状筛,要按几何筛**(2026-09-26 16:15 真实页,回归事故)。之前那条
  "文字 ≤2 字符、后代也没字"看着安全,实际把**日历的日格**也放了进来(空白补位格没文字、1 号格只有一字符)。
  面板里 8 个"按钮"实测位移全是 `0`,而出生日期被写成了 `2004-01-01` —— 探测时点中了一格,
  而**点格子改的是值,抬头当然一动不动**。现在的判据:和抬头**同一条横带**(上下边缘重叠,留 4px)、
  ≤80×80、≤2 字符、无数字/今天/此刻/现在/选择/本月、没有带文字的后代。日格、星期表头、「今天」都在抬头下面,
  横带一卡就进不来。
- **"探测式点击"必须自带停手护栏**。光靠"点错只多翻一页"这个前提是错的 —— 只要点到的东西会**写值**,
  就已经污染了表单。现在 `navigate` 每次点前后都回读 `el.value`,变了就立刻停手、
  把改成的值报进 `🔍 诊断`(`探测翻页按钮时点到了 td.dp-cell「1」,把值改成了…,已停手 —— 这一项请手选并核对`),
  并放弃后续点击。同理,**诊断里要写"点的是哪个节点"而不只是数字**:位移全 0 那一次,
  如果报的是 `td.「1」=不动、span.prev-month=+1`,一张截图当场就能定案,不用再来一轮猜。
- **子弹表里的「开始时间」是年月值(`2023-09`),北森给的面板根本没有日格** —— 只写整日期那一种
  (`openDate`)等于没支持它。现在按值的形状分派:带日 → `openDate`;只有年月 → `openMonth`
  (翻年 + 点「9月」);`至今` → 勾行内那个勾选框(行里找不到就往上一层,只在那层**恰好一个**「至今」时才点)。
  另外**勾选框/单选框不参与子表的列分组**:「至今」和结束时间同行,不排掉它会被当成该列的"第二行"。
- **夹具里两个连着写的 IIFE 少了分号 = 第二个静默不执行**。`})()` 后面紧跟一行 `(() => {`,
  ASI 不会补分号,于是被解析成"把上一个 IIFE 的返回值再调用一次" → `TypeError: (intermediate
  value) is not a function`,而**第一个 IIFE 的监听器已经挂上了**,看着像"组件坏了"。查这种问题
  别猜:在 IIFE 末尾塞一个 `window.__ready = true` 探针,一次导航就能看出它到底跑没跑完。
- **content script 跑在 isolated world**,页面控制台默认是主世界 —— 探针里读 `window.__autofill`
  恒为 `undefined`,会误报"扩展没注入"(引擎其实工作得好好的)。所以 `test/probe.js` 只读 DOM、
  不碰扩展内部对象;真要在控制台里调引擎,把上下文下拉从 `top` 切到扩展那一栏。
- 被 HTTP 复用的函数**不能 `sys.exit()`**:那会让 worker 直接退出,前端只收到一个空 500。业务错误统一抛 `LedgerError`。
- 同名常量会**静默互相覆盖**:模块里 `RANK` 先是精排 JSON 路径、后面又被状态深浅字典重新赋值,
  于是 `ledger.py init` 拿到的是字典。现在分成 `RANK_JSON` 与 `STAGE_RANK`。
